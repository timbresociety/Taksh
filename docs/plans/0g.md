# 0G integration plan

Branch: `feat/0g-integration`. Targets all three non-Continuity 0G tracks ($12,000 total). Track rules live in `docs/integrations/README.md`, API details in `docs/integrations/0g.md`.

| Phase | Track | Prize | Estimate |
| --- | --- | --- | --- |
| 0. Accounts and keys | all | | 20 min, needs you |
| 1. 0G as the game generator | Build with 0G Private Computer | $5,000 | 2 h |
| 2. A rival with a body | Physical AI | $5,000 | 4 h |
| 3. The director pays its own bills | Agents That Pay for Themselves | $2,000 | 3 h |
| 4. Submission pack | all | | 1.5 h |

Phase 1 comes first because phases 2 and 3 call the same router client.

## What we know about the router

- `https://router-api.0g.ai/v1`, OpenAI-compatible. Plain `fetch` covers it, so there's no new dependency for inference.
- `sk-` key for inference, `mk-` key (scope `account:read`) for balance and usage. Both stay server-side.
- Every response carries `x_0g_trace.request_id`, `provider` and `billing.total_cost` (in neuron, 1e18 = 1 0G). That's the request ID every track asks for.
- `X-0G-Provider-Trust-Mode: private` routes only to TeeML providers. TeeML models live today: `glm-5.3`, `0gm-1.0-35b-a3b` (accepts images, supports `response_format`), `vela-2.0-9b`.
- Claude models are on the router too, but only on the `standard` tier with no attestation. We use them only for comparison.
- `X-0G-Provider-Max-Price-Usd-Prompt/Completion` is a hard price ceiling per request. Error codes we handle: `402 insufficient_balance`, `429` (honor `Retry-After`), `503 no_provider_for_trust_mode`.

## Phase 0. Accounts and keys (you)

1. Sign in at https://pc.0g.ai, deposit a few 0G to the Payment Layer, then create an `sk-` key (trust mode Private) and an `mk-` key (Read-only).
2. Make a fresh wallet for the agent (phase 3) and fund it from https://faucet.0g.ai or with mainnet 0G. Its private key goes only in `.env.local`.
3. Ask at the 0G booth or in Discord: is there a testnet router? What is the Payment Layer `deposit` ABI? How does "sign in with your 0G account" work for the iAI bonus? None of the three is in the docs.

New env vars in `.env.example`: `OG_API_KEY`, `OG_MANAGEMENT_KEY`, `OG_MODEL` (default `glm-5.3`), `OG_AGENT_PRIVATE_KEY`, `OG_RPC_URL`.

## Phase 1. 0G as the game generator

The pipeline already talks to any object with `complete()` (`src/lib/pipeline/provider.js`). 0G becomes a third provider and the default.

1. `src/lib/pipeline/provider-0g.js`. `complete({ stage, system, user, schema })` posts to `/chat/completions` with `response_format: { type: "json_object" }` and the schema in the system prompt. It sends the trust-mode `private` header and the price ceiling, then returns `{ data, ms, usage, trace }`. `check0g()` hits `GET /v1/models` and confirms the model is TeeML.
2. `provider.js` picks 0G when `OG_API_KEY` is set, then Claude, then fixtures. `TAKSH_PROVIDER=0g|claude|fixture` forces one.
3. Pass `trace` through `meta()` in `pipeline.js` so every intent, generate and revise response carries its request ID and cost. `/api/status` reports the trust tier.
4. UI: a small "Generated on 0G · private TEE · req_… · 0.0019 0G" line on the brief and result screens, with a link to the receipt. This is what judges see.
5. Quality check: `npm run eval -- --model glm-5.3` and `--model 0gm-1.0-35b-a3b` against the existing case set. Keep whichever passes validation more often. The repair loop in `generateGame` already absorbs some JSON drift.
6. Test: `test/provider-0g.test.mjs` with a stubbed `fetch`. It covers that the trace is parsed, a 402 becomes a readable message, and a 503 gets one retry.

Why users come back: every idea becomes a new game you play with your body, and the prompt never leaves the enclave.

What breaks without 0G: Taksh can't turn an idea into a game, so you're left with 13 canned fixtures.

iAI bonus (stretch): the user signs in with their 0G account and watches credits drop. It's blocked until the booth question in phase 0 gets an answer. The Router's Direct path (user wallet signs each request) looks like the fit. The Privy origin rule means it only works on localhost:3000, our dev port.

## Phase 2. A rival with a body

Each game template already has a `bot(state, skill)` and a seeded RNG (`createRandom` in `src/lib/templates/shared.js`). So any episode replays exactly from its action log. The rival is a second rigged character in the 3D stage whose moves come from a 0G model, not from `bot()`.

1. Start with one template: `lane_runner` (Local Dash). Add `observe(state)` to it. It returns a short text view of the rival's lane, the next 3 obstacle rows and the score.
2. `src/lib/agent/rival.js`. Every 800 ms it sends the observation to `/api/rival/decide`, which calls 0G (`0gm-1.0-35b-a3b`, private) with the allowed actions. The model answers with one action. Each decision is logged as `{ t, observation, action, request_id, provider, cost, ms }`.
3. Safe stop. If 0G times out (1.5 s), errors, or the balance is empty, the rival freezes in a "signal lost" pose and logs `safe_stop`. It never falls back to `bot()`, because a faked decision disqualifies the entry.
4. Episode log on 0G Storage. When the round ends, `/api/rival/episode` uploads the log JSON with `@0gfoundation/0g-ts-sdk` and returns the root hash. The result screen shows the hash and an explorer link.
5. Replay. `npm run replay-episode -- <rootHash>` downloads the log, rebuilds the game from its seed and applies the actions at their timestamps. The final score has to match. That match is the check, and it goes in `test/`.

Fit risk: the track's examples are robots (zerobot, MuJoCo, LeRobot). Our body is a simulated one in a 3D world, which their "replayable simulation" option allows. The pitch is a player racing a 0G agent, with both bodies on screen. I'd confirm with 0G at the booth before spending all 4 hours.

## Phase 3. The director pays its own bills

The director is the server-side agent that generates games. Players pay it, and it keeps its own 0G compute balance topped up.

1. Payment in. The play screen shows "Generate a game: 0.01 0G" with the agent's address. The browser sends the payment through `window.ethereum` (no wallet library) and posts the tx hash to `/api/pay`. The server checks the receipt on-chain before it unlocks a generation.
2. Top-up loop. `src/lib/agent/treasury.js` runs on an interval. It reads the router balance (`GET /v1/account/balance`, `mk-` key). When the balance drops under a threshold and the wallet holds enough, it deposits into the Payment Layer (`0xA3b1…cE32` mainnet). Each deposit's tx hash is logged.
3. Spending controls. The price-ceiling headers go on every call, plus a daily spend cap in code tracked from `billing.total_cost`. When funds run low, new generations wait in a queue and the screen says so. A `402` falls back to labelled fixtures. It never retries forever.
4. Ledger page `/agent`: payments in (tx hashes), deposits (tx hashes), inference out (request IDs and cost), and the current balance. The demo is this page updating with no one touching a wallet.
5. Test: the treasury decision (deposit or not, queue or not) as a pure function with a small `test/treasury.test.mjs`.

Blocked on: the Payment Layer deposit ABI (phase 0, question 3). Fallback: the comfy.fun route (agent token, fees fund compute) via `comfy-cli`. It's documented, but it's a bigger detour.

New dependency: `ethers` (the 0G storage SDK needs it anyway), used for receipts and the deposit.

## Phase 4. Submission pack

0G wants all of these on every track:
1. README: setup steps, env vars, an architecture diagram, contract and wallet addresses, plus the one-line "what breaks without 0G".
2. Demo video under 3 minutes. Idea, then the game generated on 0G (request ID visible), then racing the 0G rival (decision log), then the storage root hash, then the `/agent` ledger.
3. Live demo link. The game runs fine deployed, but the iAI login works only on localhost.
4. Team Telegram/X handles in the submission.

## Out of scope

- Fine-tuning, image generation, audio. No track asks for them.
- Moving the existing Claude path. It stays as an option behind `TAKSH_PROVIDER=claude`.
- Rivals for the other 12 templates. Add `observe()` to each one only after the first rival plays well.
